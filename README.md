# resume-jd-matcher

把「岗位描述 JD」+「原始简历」变成一份**聚焦、可扫读、逐条命中 JD 支柱**的 Markdown 简历的 AI Agent Skill。

这不是文笔润色工具。核心动作是**重排证据、补强缺口、剔除无关、规避雷区**——让简历的每一条都对应 JD 的某根支柱。

## 为什么单独做一个 Skill

通用「简历优化」最容易犯三种错：把简历越写越长、把没做过的方向硬编上去、把上一份 JD 的关键词套到新 JD 上。

这个 Skill 把一次真实交付中踩过的 **19 个坑**固化成检查清单：动笔前先问清 4 类关键信息，写完按清单自检。方法论在 `SKILL.md`，证据在 `references/pitfalls.md`。

## 核心原则

| # | 原则 | 含义 |
|---|---|---|
| 1 | 主张 + 证据 | 每段能力后用真实项目佐证，忌空话 |
| 2 | 聚焦不堆砌 | 代表项目约 4 个，**替换而非叠加**，避免稀释主线 |
| 3 | 不夸大、不硬编 | 零证据方向宁可留白或补学习叙事，不造假 |
| 4 | 简洁可扫读 | 个人优势用「加粗标题 + 一句」，所有 URL 转内嵌可点链接 |
| 5 | 先问后写 | 动笔前收齐 4 类关键信息，禁止凭空假设 |

## 工作流（6 步）

| Step | 动作 | 关键点 |
|---|---|---|
| 1 | 读取与解析输入 | JD 可是截图 / 文字 / 链接；图片与链接**先如实提取全文**，不凭直觉总结 |
| 2 | 动笔前必问 4 问 | 公司行业类型、领域聚焦主线、高层对话经验真实性、项目规模定位 |
| 3 | 匹配度对照 | 产出「JD 要求 ↔ 现状 ↔ 结论」表，标出强匹配 / 补标签 / 短板 |
| 4 | 写第一版 Markdown | 保持原简历骨架，只替换与重排内容；量化成果下沉到代表项目 |
| 5 | 迭代优化 | 精简优势、删「对应 JD」标注、按售前/实施取舍动作、全篇去重、回填**本 JD 原词** |
| 6 | 收口与导出 | 按 `名字_岗位名称.md` 重命名；PDF 优先用本机 Chrome 无头 `print-to-pdf` |

> Step 2 的 4 问直接决定措辞与聚焦方向，跳过必然返工。若用户已主动提供某项，可省略对应问题。

## 19 条踩坑速览（节选）

| 坑 | 正确处理 |
|---|---|
| 客户是上市集团却自贬「中小型客户」 | 确认可升级后点名规模，只写真实情况 |
| JD 要 CTO 对话，实际只对接 IT 负责人 | 弱化为「技术互信 / 方案影响力」，不造假 |
| JD 列的方向零证据 | 不硬编，留白或补学习叙事 |
| 项目涉及逆向 / 灰产手法表述 | 改中性合规措辞（目标公司体系内尤其高危） |
| 想用出单 / GMV 证明价值 | 只拿工程指标：拦截率、发布成功率、效率提升 % |
| 项目标题挂「（对应 JD：…）」 | 交付版一律删，只留「项目名｜能力定位」 |
| 售前岗写了培训 / 答疑 / 交付 SOP | 删售后动作。**成交前说的是售前，成交后干的是售后** |
| 套用上一份 JD 的词汇 | 每换一个 JD 重抄词库，回填本 JD 原词 |
| 同文件并行多次编辑 | 串行执行，改前 Read、改后再 Read 校验 |
| 导出 PDF | SQL 不可能；优先本机 Chrome 无头渲染，零安装 |

完整清单见 [`references/pitfalls.md`](references/pitfalls.md)。

## 安装

遵循 `SKILL.md` 约定的 Agent 均可直接使用，放到对应 skills 目录即可：

```bash
# WorkBuddy
cp -r resume-jd-matcher ~/.workbuddy/skills/

# Claude Code
cp -r resume-jd-matcher ~/.claude/skills/
```

## 使用

把 JD（文字 / 截图 / 链接）和原始简历一起交给 Agent，说「按这个 JD 优化简历」。Agent 会先问 4 个问题，再产出 Markdown 简历；需要时可继续要求精简、换项目、导出 PDF。

**适用**：中文岗、有原始简历素材、针对性改写。
**不适用**：纯排版美化、从零无素材写简历、英文简历润色。

# 飞书云盘交付流程

用户要求把优化后的简历「写入飞书云盘 / 云空间」「按公司与岗位建目录归档」时使用。先读取并遵循 `lark-drive` 与 `lark-doc` 的最新 Skill；目录和导入走 Drive，云端正文读取与后续编辑走 Doc。

## 1. 读取最新简历与确认命名

- 写入前重新读取本地 Markdown，禁止使用对话中的旧版本。
- 目录默认命名为 `公司名称＋岗位名称`，如 `萤石开放平台技术支持`；父目录未指定时放在云盘根目录。
- 用户当轮明确给出目录名时以用户命名为准；若该名称与已确认的公司或岗位存在错字、别名等冲突，先澄清再创建。
- 飞书文档标题**只写姓名**（当前用户为 `季忠健`），不得追加 `_岗位名称`、公司名或其他后缀；本地 Markdown 文件名仍保持 `名字_岗位名称.md`。

## 2. 检查或创建目录

先按完整标题搜索，避免重复创建：

```bash
lark-cli drive +search --as user --query '公司岗位名称' \
  --only-title --doc-types folder --format json
```

- 无严格匹配：在用户指定位置创建；未指定则在根目录创建。
- 唯一严格匹配：复用该目录，不重复创建。
- 多个严格匹配或归属不清：停止写入并让用户确认目标目录。

```bash
lark-cli drive +create-folder --as user --name '公司岗位名称'
# 指定父目录时增加：--folder-token '<PARENT_FOLDER_TOKEN>'
```

保留返回的 `folder_token` 与目录 URL，供导入和最终交付使用。

## 3. 导入为飞书在线文档

默认把 Markdown 导入为**可编辑的在线 docx**，不要作为原生 `.md` 文件上传；只有用户明确要求保留原生 Markdown 时才走 `lark-markdown`。

导入前基于最新本地 Markdown 生成一个**临时导入副本**：

- 仅当首个非空行是一级标题 `# 姓名` 时，删除该行及其后的连续空行，使「手机 / 微信｜邮箱」成为正文第一行，其余内容顺序不变。
- 若首个非空行不是姓名 H1，先核对结构，禁止盲目删除其他内容。
- 不修改原始本地 Markdown；本地文件仍保留 `# 姓名`，删除姓名 H1 只作用于飞书导入副本。

```bash
lark-cli drive +import --as user \
  --file '/absolute/path/飞书导入临时副本.md' \
  --type docx \
  --folder-token '<FOLDER_TOKEN>' \
  --name '季忠健'
```

- 必须显式传 `--name`；值仅为姓名（当前用户为 `季忠健`），不得使用源文件名或追加岗位名称。
- 多个文件导入同一目录时串行执行，禁止并发。
- 返回 `ready=false` 或 `timed_out=true` 时，按返回的 `next_command` 查询任务，不盲目重新导入。
- 导入失败时按错误处理；不要重复创建目录或生成多份简历。

## 4. 核验与交付

导入成功后，重新读取云端文档全文，核验标题、正文开头与主要章节：

```bash
lark-cli docs +fetch --as user --doc '<DOCUMENT_URL>' \
  --doc-format markdown
```

至少核验：

- 文档标题仅为 `季忠健`，不含岗位名称；
- 正文不存在姓名 H1，首个可见正文为手机 / 微信与邮箱；
- 个人优势、工作经历、代表项目、教育与认证等章节完整，正文无截断。

最终同时交付：

1. 云盘目录链接；
2. 飞书在线简历链接。

使用 `present_files` 交付两个链接，并简要说明导入和核验结果；不要在回复中暴露 token。

## 5. 后续编辑与同步边界

- 用户继续修改云端简历时，**必须先重新读取该云文档最新版本**，再按 `lark-doc` 更新原文档并重新交付；不要重新导入生成副本。
- 用户继续修改本地 Markdown 时，先读取本地最新文件；如用户要求同步到云端，仍应更新既有云文档，而不是再次导入。
- 本地 Markdown 与云文档不会因一次导入自动持续同步；不要宣称两者已实时同步。
